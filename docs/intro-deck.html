Model Landscape

Databricks-native ML observability for training experiments and production inference. One app. One SDK. Zero additional cost.

The Problem

MLflow logs everything faithfully. But it doesn't explain which run to pick, whether data has shifted, or what anything costs.

📊

No ranked comparison

MLflow shows a flat metric table. No deltas, no ranking, no narrative across training runs.

📈

No training drift

Production drift monitoring exists. Training-run drift -- feature shifts between retrain cycles -- is entirely unserved.

💰

No cost attribution

System tables have compute cost data but it's disconnected from experiments. No tool answers "how much did this sweep cost?"

🚫

No batch monitoring

Lakehouse Monitoring requires a serving endpoint. Batch inference models have no native monitoring path.

🛠

No incident lifecycle

When drift degrades a model, there is no built-in way to track the incident from detection through resolution.

🔍

No fleet visibility

No single pane to see the health of every model in production. Teams build ad-hoc dashboards or fly blind.

Model Landscape

Training experiment comprehension + production inference monitoring. Two components, one shared analytics engine, deployed inside your workspace.

Two Components

SDK enriches training runs. App monitors production inference. Both share the same drift math.

Python SDK

mlflow-lens

Thin convenience layer on MLflow. Composes with mlflow.start_run(), never replaces it.

  • experiment.auto_log_context() -- workspace, cluster, git SHA
  • summary.log() -- structured summaries for fast comparison
  • drift.log_drift() -- PSI + KL + JS between training runs
  • panels.log_panel() -- confusion matrix, ROC, feature importance
  • cost.log_cost_context() -- tags for system table cost joins
  • export.to_delta() -- bridge to Lakeview dashboards
Databricks App

Model Landscape

Production-grade monitoring. Point at any UC inference table. Four clicks to deploy.

  • Experiments -- ranked runs, metric deltas, comparison
  • Drift Analysis -- PSI/KL/JS heatmap over time
  • Performance -- degradation contributors by feature bin
  • Data Quality -- row counts, null rates, prediction stats
  • Incidents -- open / escalate / downgrade / recover
  • Onboarding -- 4-step wizard with auto-discovery
mlflow_lens.analytics.drift -- canonical drift math (PSI + KL + JS with stable histogram edges). SDK owns the engine. App consumes it.

Get Started

One bundle. Any Databricks workspace. No external dependencies.

# Deploy Model Landscape
databricks bundle deploy -t warehouse_only \
  --var "sql_warehouse_id=<id>" \
  --var "refresh_node_type_id=<node-type>" \
  --var "control_plane_catalog=<catalog>" \
  --var "control_plane_schema=<schema>"

# Start the app
databricks apps start model-landscape
databricks apps deploy model-landscape --source-code-path ...
