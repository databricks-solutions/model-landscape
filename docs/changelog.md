# Changelog

All notable changes to **Model Landscape** are tracked here. The format
is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and
this project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Versions apply to the whole product. The mlflow-lens SDK wheel ships
under the same version as a tagged GitHub Release
(`mlflow-lens-vX.Y.Z`).

## [0.2.0] — 2026-05-27

### Added

- **mlflow-lens panel quick functions** modeled on Yellowbrick — Plotly-only,
  no matplotlib dep.
    - **Classifier** (`mlflow_lens.classifier`): `roc_auc`,
      `confusion_matrix`, `precision_recall`, `classification_report`,
      `class_prediction_error`, `discrimination_threshold`.
    - **Regressor** (`mlflow_lens.regressor`): `prediction_error`,
      `residuals`, `alpha_selection`.
    - **Model selection** (`mlflow_lens.model_selection`):
      `learning_curve`, `validation_curve`, `feature_importances`,
      `cv_scores`.
    - Each quick function returns a `plotly.graph_objects.Figure`,
      exposes a pre-computed entry point (`.from_scores`,
      `.from_predictions`, or `.from_values`), and on `log=True` writes
      both the JSON data (`lens/panels/<type>.json` — warehouse-app
      contract) and an interactive HTML figure
      (`lens/panels/<type>.html` — opens in the MLflow UI).
- **Shared Plotly theme** in `mlflow_lens._plotly_theme.lens_layout`
  (Databricks-flavored colorway, `plotly_white` base).
- **`mlflow_lens.panels.PANEL_TYPES`** extended from 4 → 13 types; new
  types: `classification_report`, `precision_recall_curve`,
  `class_prediction_error`, `discrimination_threshold`,
  `prediction_error`, `residuals`, `alpha_selection`,
  `validation_curve`, `cv_scores`.
- **Numpy-aware JSON encoder** in
  `mlflow_lens._artifacts.log_json_artifact` so user-supplied
  `np.int64` labels round-trip cleanly.
- **MkDocs Material docs site** covering the whole product — landing
  page + intro deck + getting-started + concepts + app architecture
  and deploy guides + SDK API reference (auto-generated by
  mkdocstrings) + 13-panel interactive Plotly gallery + changelog.
- **GitHub Pages workflow** (`.github/workflows/docs.yml`) — strict
  build on PRs that touch the docs or SDK source, deploy on push to
  `dev`, `main`, or `mlflow-lens-v*` tag.
- **mlflow-lens GitHub Release workflow**
  (`.github/workflows/mlflow-lens-release.yml`) — on tag push: build
  sdist + wheel, `twine check`, smoke-install in a clean venv, publish
  GitHub Release with attached wheel + sdist + `SHA256SUMS` and
  auto-generated notes.
- **`generate_fraud_training_set`** in the tutorial data generator,
  sharing baseline distributions and signal weights with
  `generate_fraud_inference` so a model trained on this set sees ~0
  PSI on day-0 inference (no train/serving skew at baseline).
- **`MODEL_LANDSCAPE_FIXTURE_NOW` env var** for deterministic
  reproducibility of wall-clock-sensitive data-generator output in
  tests (pinned via `_fixture_now()` / `_fixture_today()` helpers).
- **`make_monitor_config`** helper in
  `tutorial/_resources/monitors.py` that bakes in the standard
  baseline policy, cadence presets, and `schedule_enabled=True` so
  notebook callsites focus on what's different per monitor.
- **Champion precheck** at the top of `02_observe_and_recover` — if
  notebook 01 hasn't shipped a Champion alias, fail fast with an
  actionable message instead of a cryptic Spark UDF load error 20
  lines later.

### Changed

- **mlflow-lens is now a uv workspace member at the repo root**
  (`mlflow-lens/`) with its own `pyproject.toml`, README, LICENSE,
  NOTICE, and release pipeline. The warehouse app stays at
  `model_landscape/` and pulls in mlflow-lens via the workspace.
- **Tutorial collapsed from 5 notebooks to 2**:
  `01_train_and_ship` (features → train 3 candidates → mlflow-lens
  panels → register Champion) and `02_observe_and_recover` (score →
  60 days of drifted inference → bootstrap monitors → investigate →
  retrain v2 → deploy).
- **Tutorial notebooks use the new mlflow-lens quick functions**
  instead of hand-rolled `panels.log_panel(...)` calls. Each panel
  now contributes both a structured JSON artifact and an interactive
  Plotly HTML to the run.
- **`tutorial/_resources/00_setup.py`** collapsed the duplicate
  `table()` / `model_name()` helpers into a single `fqn()` function.
- **Documentation unified.** README at the repo root is now a thin
  pointer to the site; the standalone `docs/*.md` files (architecture,
  deploy, existing-app) are first-class pages on the site instead of
  three separate sources of truth.
- mlflow-lens runtime deps now include `plotly>=5.24` and
  `scikit-learn>=1.5`.

### Removed

- `docs/WORKSPACE_SMOKE_TEST.md` — internal QA runbook, moved out of
  user-facing docs.
- `docs/MLFLOW_LENS_SDK.md` — redundant with the mkdocstrings-generated
  API reference (design philosophy preserved in `concepts.md`).
- `docs/databricks-logo.webp` — unreferenced asset.
- `VERSION` file at the repo root — `pyproject.toml` is now the
  single source of truth.
- `Dockerfile` — unused.

## [0.1.1] — 2026-05-26

### Changed

- **Dash 2.x → 3.x major bump** in the app and monitor runtimes,
  dropping the deprecated `dash-core-components`,
  `dash-html-components`, and `dash-table` shims (imports already used
  `from dash import dcc, html`, so no app code changed).
- Resolved 16 Dependabot alerts spanning `urllib3`, `gitpython`,
  `idna`, `flask`, `werkzeug`, and `starlette`. The Dash 3 bump removed
  the `flask < 3.1` cap that had been blocking some of these upgrades.
- Rebuilt `NOTICE.txt` as a structured license table with each
  transitive package listed alongside its SPDX identifier.

## [0.1.0] — 2026-05-12

Initial public release. Repo moved from
`databricks-field-eng/model-landscape` to
`databricks-solutions/model-landscape`.

### Added

- **Warehouse-backed control plane** in Unity Catalog Delta tables:
  `monitor_configs`, `drift_metrics`, `quality_metrics`,
  `performance_metrics`, `incidents`, `incident_history`,
  `refresh_runs`, and supporting daily-profile / class-aware tables.
- **Optional Lakebase read model** for accelerated app reads in `dev`
  and `prod` deployment targets.
- **Multi-page Dash app** with the operator control plane: Overview,
  Incidents, Drift Analysis, Feature Deep Dive, Performance, Data
  Quality, Monitor Settings, Onboarding (staged wizard).
- **Shared Spark refresh workflow** that recomputes drift, performance,
  and incidents on a schedule for all active monitors, with
  serial-per-monitor execution by default.
- **External labels support** with configurable join keys, order
  columns, dedupe, and matched-vs-unmatched preview at activation.
- **Rolling and fixed baseline policies**; binary classification and
  regression monitoring; categorical drift; incident lifecycle.
- **mlflow-lens SDK 0.1** under `src/mlflow_lens/`:
    - `experiment.auto_log_context()` — workspace, cluster, runtime,
      notebook path, and git SHA as `lens.*` tags.
    - `summary.log` / `summary.build` / `summary.cache` / `summary.load` —
      structured run summaries with paginated index building (defeats
      the 1000-run MLflow cap).
    - `drift.log_drift` — PSI / KL / JS drift against a reference run
      with snapshot chaining.
    - `cost.log_cost_context` — cluster-ID tagging for system-table
      cost attribution.
    - `export.to_delta` — Delta export of the run index.
    - `panels.log_panel` — low-level panel artifact API with 4 panel
      types (`confusion_matrix`, `roc_curve`, `feature_importance`,
      `learning_curve`).
    - `analytics.drift` — shared PSI / KL / JS engine used by both
      mlflow-lens (training-time) and the warehouse app (production).
- **Databricks Asset Bundle** deployment with `warehouse_only`, `dev`,
  and `prod` targets; refresh and tutorial workflows.
- **Five-notebook MLOps tutorial** (collapsed to two in 0.2.0).
